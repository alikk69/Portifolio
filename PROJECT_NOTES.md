## How to preview locally

A `.claude/launch.json` config named `portfolio-site` runs `python -m http.server 8791 --directory portfolio-site` — use the Browser tool's preview_start with that name rather than a raw `python -m http.server` command. **Note:** the server dies mid-session fairly often — if a load fails, just restart it (`preview_start` with the same name). Browsers also cache `style.css`/`script.js` aggressively — both are loaded with a `?v=N` cache-busting query string in `index.html`; **bump both version numbers on every edit** or changes won't show up.

## "Polish both versions" round — real bugs found via code reading, not just visual scanning (2026-08-12, 14th round)

Owner asked to polish the desktop and mobile experiences generally. Rather than only eyeballing screenshots, cross-checked animation code paths against their live computed end-state — this surfaced three **genuine, permanent bugs** that had nothing to do with the session's known rAF/paint-pausing test limitation (round 12's note). Worth internalizing: when something looks visually "off" or "stuck," don't default to blaming the test tab — check whether the source actually reaches the state you expect first.

- **Achievement modal opened off-screen once you'd scrolled down the page.** `.ach-modal-overlay` (`position:fixed`) sits nested inside `<section id="achievements" class="section reveal ...">`. `.reveal.in-view` animated to `transform: translateY(0)` — and *any* non-`none` transform on an ancestor (even a harmless-looking identity-ish one) creates a new containing block for `position:fixed` descendants per the CSS spec, so the "fixed" overlay was actually positioned relative to that scrolled-away section instead of the viewport. Fixed by changing the end state to `transform: none` — animates identically (browsers interpolate `translateY(28px) → none` the same as `→ translateY(0)`), but no longer creates that containing block. - **Every education-timeline item sat permanently shifted 40px left of where it belonged**, dragging `.education-dot` off toward the viewport edge (visually looked like a stray dot floating near x=0). - **The name "Ali Nadeer Ezbayel" could wrap mid-word** ("Ezbay" / "el" on separate lines) at narrow widths. `letterReveal()` splits heading text into one `<span class="letter-char">` per character as flat siblings — with letters as separate adjacent inline boxes and no wrapping structure tying a word together, the browser can insert a line break between any two letters, not just at real spaces (a known issue with letter-by-letter split-text effects, e.g. why GSAP's own SplitText wraps words before chars). Fixed by grouping each word's letters inside a `display:inline-block; white-space:nowrap` wrapper span, with a real space text node between word-wrappers — same visual per-letter cascade animation, same `chars` array passed to GSAP, just can't break mid-word anymore. ## Card rebuilt on native sticky + scroll-derived progress — the actual spec (2026-08-13, 31st round)

The owner supplied the original Claude Design motion spec and asked for it followed exactly. Doing so resolved every remaining complaint at once, because the spec's architecture is what makes the behaviour they wanted structurally guaranteed rather than something to be tuned toward.

**The insight I'd missed across four rounds**: the reveal must be a *pure function of scroll position*, recomputed every frame — not an animation with a start, an end, and state in between. Every previous attempt animated *toward* a target and therefore had a state that could latch (`onEnter`-only → stuck open), lag (ScrollTrigger `scrub`'s catch-up smoothing → the "laggy" complaint), or desync from layout. With `progress = -sectionTop / (sectionHeight - viewportHeight)` there is no state at all: scrolling up recomputes a lower number and the card goes back in, necessarily. Verified by sweeping down then back up — the measured card position at a given scroll offset is *identical* in both directions.

- **Structure** (per spec): `.cc-scroll` is a 220vh spacer; inside it `.cc-sticky` is `position: sticky; top: 0; height: 100vh` and flex-centres the card stage plus the security ticker. The heading and intro stay in normal flow *above* `.cc-scroll`. This is why the card can no longer cover text — it only moves while the sticky frame is pinned, by which point the heading has scrolled off on its own. Not a margin calculation; a structural guarantee.
- **Native CSS sticky, not a GSAP pin.** Avoids the shared-`matchMedia`-block pin-ordering constraint entirely (see round 28's notes), and avoids GSAP `scrub` lag. Nothing about the scroll is hijacked.
- **Had to remove `overflow: hidden` from `#contact`** — it makes the section a scroll container and silently breaks `position: sticky` in descendants. It was only there to clip a soft radial glow that already fades to transparent before its own edges, so nothing needed it.
- **Motion values ported exactly from the spec**: y 22 → −172, rotation −4 → 0, scale 0.97 → 1, opacity ramp over the first 0.02 of progress, shadow 0.12 → 0.5, `pointer-events` gated at progress > 0.5, and the two-phase mech curve (linear to 0.82 over 0 → 0.75, then decelerating settle over 0.75 → 1). The spec explicitly warns a single ease across the whole range makes the settle feel abrupt — kept as two phases.
- **Shine reimplemented per spec** as `background-size: 250%` + `background-position` keyframes with progress-driven **plain opacity**. The spec flags `mix-blend-mode` here as the cause of a previous full-card blackout inside a sticky + nested-transform ancestor chain; left a comment on the rule so nobody reintroduces it. **Careful**: the old `@keyframes cc-sweep` the card used is still referenced by `.config-output` and `.ach-card::before` — nearly deleted it as dead code, caught by grepping before removing.
- **Reduced motion**: card renders fully out and static, and `.cc-scroll`/`.cc-sticky` collapse to normal flow, so those users don't scroll through a screen and a half of nothing for an animation that never plays.
- **Verified** at 390×844 and 1280×800 by sweeping 41 points across the full scroll range: never covers the heading or intro at any point, never leaves the viewport, rises monotonically (no jumps), tucks fully inside the pocket at rest, clears it by 60px at full reveal, links only clickable once clear, page ends with the card in frame and 0px trailing blank space, no console errors.
- **Testing note**: this pane freezes `requestAnimationFrame` *and* CSS transitions. Since the reveal is rAF-deferred, the fix is to replace `window.requestAnimationFrame` with a synchronous shim (with a recursion-depth guard, or self-rescheduling render loops hang the tab — that hang cost a call this round) and set `transition: none` on the card before measuring. That exercises the real handler rather than simulating it.
- Cache-busting bumped to `style.css?v=45`, `script.js?v=76`.
